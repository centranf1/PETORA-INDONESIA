# 03 — Functional Requirements Document (FRD)

**Status:** Rancangan fungsional; semua alur berikut perlu review pemilik domain sebelum implementasi.  
**Konvensi:** API pada kolom “API operasi” adalah kontrak usulan, bukan endpoint yang sudah ada. Role/action tetap dibatasi branch/data scope backend. Setiap mutation memvalidasi input, status, permission, dan menulis audit; format kegagalan standar dijelaskan di [API specification](../02-ARCHITECTURE/08-API-SPECIFICATION.md).

## 1. Pola penerapan lintas fitur

- **Aktor:** role pada tabel fitur adalah aktor tipikal, bukan grant otomatis. Aksi ditolak bila permission atau scope tidak sesuai.
- **Field umum:** `id`, `branch_id` pada transaksi, `status`, `created_at`, `created_by`, `updated_at`, `updated_by`, nomor referensi unik sesuai domain.
- **Validasi umum:** required fields, tipe/range, foreign key aktif, cabang yang diizinkan, status transition, duplikasi/idempotency dan kebijakan data sensitif.
- **Audit:** record actor, waktu, entitas, action, hasil, correlation/reference; jangan menaruh credential atau konten medis yang tidak dibutuhkan di audit.
- **Error:** `VALIDATION_ERROR`, `NOT_FOUND`, `FORBIDDEN`, `CONFLICT`, `INVALID_TRANSITION`, `CAPACITY_EXCEEDED`, `INSUFFICIENT_STOCK`, `PAYMENT_FAILED`, `INTEGRATION_UNAVAILABLE`. UI mempertahankan input yang aman, menjelaskan langkah perbaikan, dan tidak menampilkan success palsu.
- **API:** semua endpoint di bawah memerlukan auth; implementasi wajib menerapkan permission action dan filter scope di server.

## 4. Aturan status dan transisi

Status yang disajikan adalah baseline usulan, tidak semua domain wajib memakai satu enum. Terminal status tidak dapat diubah langsung menjadi status aktif; pembatalan/refund/correction memakai operasi kompensasi dan permission. Transisi penuh serta pemisahan order vs fulfillment/payment ditetapkan pada refinement domain. Lihat [glosarium](./22-GLOSSARY-DATA-DICTIONARY.md).

## 5. Entitas, API, notifikasi, dan exception

Entitas relasi utama untuk setiap fitur disebut di tabel dan dielaborasi pada [database design](../02-ARCHITECTURE/06-DATABASE-DESIGN.md) serta [ERD](../02-ARCHITECTURE/07-ERD.md). Kontrak API lengkap ada pada [API specification](../02-ARCHITECTURE/08-API-SPECIFICATION.md). Kegagalan umum mencakup validasi, akses ditolak, data tidak ditemukan, konflik status, kapasitas habis, stok tidak cukup, provider timeout, dan konflik concurrent update. Sistem wajib menyampaikan error dengan aman, tidak menganggap kegagalan sebagai sukses, dan mengaudit operasi sensitif.

## 6. Kriteria penerimaan lintas modul

- Semua mutasi memeriksa authorization di server dengan branch/data scope.
- Setiap transaksi membawa branch yang benar; master global dibedakan dari pengaturan branch.
- State transition dan nilai keuangan dihitung ulang di server.
- Operasi retry pada payment/stock/booking idempotent atau mendeteksi duplikasi.
- Perubahan stok dan finansial mempunyai histori yang dapat direkonsiliasi.
- Notifikasi eksternal tidak menahan transaksi inti.
- Akses data pelanggan/medis menerapkan ownership, consent, assignment, dan permission.
