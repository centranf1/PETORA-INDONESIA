# Documentation Guide

Panduan ini mengatur bagaimana dokumen disusun, diperbarui, dan divalidasi.

## Document Status

Setiap dokumen memerlukan metadata dan status: Draft, In Review, Approved, or Deprecated.

## Required Structure

Dokumen harus mencakup perihal purpose, scope, background, requirements, detailed specification, workflow, security considerations, dependencies, and acceptance criteria ketika relevan.

## Change Governance

Perubahan fitur harus memperbarui PRD, workflow, dan acceptance criteria. Perubahan permission harus memperbarui permission matrix dan RLS document. Perubahan API harus memperbarui API specification.

## Traceability Rule

Setiap requirement harus terhubung dengan feature ID, module, database table, API or edge function, UI, dan test case.

## Quality Rule

Dokumen bersifat draft jika belum disetujui oleh stakeholder; tidak ada keputusan yang diklaim final sebelum approval.
